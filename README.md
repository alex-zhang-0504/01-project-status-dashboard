# 项目状态看板

## 目标

为部门 15 位项目经理的周三例会提供技术项目状态看板：项目经理只维护飞书多维数据源，看板不提供填写或回写能力。当前本地 `V1.3.0` 由脚本一键生成单文件网页；妙搭迁移完成后，负责人可直接打开托管应用并自行刷新。

## 现状

正式版 `V1.3.0` 已作为本地稳定基线保留，项目进入妙搭全栈迁移阶段。当前唯一正式模板为 `src/template-dashboard-v1.3.0.html`；`V1.0.0`、`V1.1.0`、`V1.2.0` 作为旧版本兼容文件保留，Demo1～3 保持冻结。

迁移采用“当前 Project 统一管理＋独立妙搭 App Git”：父 Git 保存本地版、项目规范、迁移方案和版本档案；`deployments/miaoda-app/` 使用自己的 Git 仓库并同步到妙搭远端。完整学习与本项目迁移方案见 `docs/miaoda-full-stack-migration-solution.md`；可跨 Project 复用的本地开发、双仓库、push、发布和线上验收规则见 `MIAODA_LOCAL_TO_ONLINE_RULES.md`。

开发期妙搭应用保持仅创建者可见，不添加协作者或其他操作者；团队内部验证延后至用户另行授权。

妙搭 App `V1.3.0` 已通过创建者发布态和开发预览态验收：App commit `ff1def1`、release `7673379105845677006`，线上首页、首次生成、重新生成和自包含离线 HTML 下载均可用；妙搭开发页已拉取同一远端版本，内嵌预览可读取真实 Base 并显示本周新增汇报。该版本已接入 Base 系统创建时间并同步本周新增汇报规则；发布前通过 lint、类型检查、生产构建、完整 Jest 和部署产物门禁。开发与线上环境使用同一正式 Base 中的三张数据表，Lookup 字段「阶段查找／状态查找」能够读取；开启高级权限的正式 Base 必须把当前文档应用添加为「可管理」，否则应用身份会返回无权限。本地 `.env.local` 中的数据表 URL、PM 相对顺序和应用凭据均不进入 Git。当前继续使用既有 CLI 应用身份验证，正式团队试点前仍需换成专用只读飞书应用并重新执行同口径验收；缺少凭据时接口明确返回 `503`，不会用空数据伪装接通。妙搭“拉取”任务额外生成的 checkpoint `a01574e`、`b27e66c` 仅存在于云端工作区，未 push、未纳入 release；后续处理须单独遵守 Git 与数据库 schema 变更确认规则。

正式看板通过 Base 字段「是否上周三例会」动态收录子任务；本地 `src/dashboard_config.json` 只配置 PM 固定相对顺序，不参与项目或子任务筛选，格式见 `src/dashboard_config.example.json`。

## 怎么运行

前置：本机 lark-cli 已登录（user 身份），可读目标 Base。

```powershell
D:\ai-workspace\shared\scripts\python.cmd `
  src\generate_dashboard.py `
  --base-url "<含 table 与 view 参数的进展 Base URL>" `
  --issue-base-url "<含 table 与 view 参数的问题 Base URL>" `
  --innovation-base-url "<含 table 与 view 参数的创新大赛 Base URL>" `
  --lark-cli "<lark-cli.cmd 路径>" `
  --config "src\dashboard_config.json" `
  --filter-field "是否上周三例会" `
  --as user
```

输出：`output/YYYY-MM-DD(WXX)-TDT技术项目状态看板.html`（`WXX` 为两位 ISO 周次；单文件自包含，可转发给其他人在本地浏览器直接打开；含真实业务数据，不入库）。同一天重复生成覆盖当天文件，跨日期自动创建新文件并保留历史日期文件。

可选参数：`--issue-base-url`（「遗留问题」视图的数据源；不传时遗留问题按钮不可用）、`--innovation-base-url`（「创新大赛项目概况」视图的数据源；不传时该区块不可用）、`--meeting-discipline`（覆盖会议内容 JSON，默认读取正式内容源 `src/meeting_content.json`）、`--page-delay`（分页间隔秒，默认 0.2）、`--run-date`（静态生成时覆盖文件名日期）、`--output-dir`（覆盖输出目录）、`--config`（正式配置路径，默认 `src/dashboard_config.json`）、`--scope`（仅旧白名单兼容模式使用，格式见 `src/demo_scope.example.json`）、`--template`（默认 `src/template-dashboard-v1.3.0.html`）、`--variant`（仅兼容旧命令，不影响正式离线文件名）。

正式收录规则为 `--filter-field "是否上周三例会"`（可配 `--filter-value`，默认「是」，勾选框 True 亦命中）。只有显式不传 `--filter-field` 时才进入旧白名单兼容模式，并要求同时传入 `--scope`；正式 `dashboard_config.json` 不保存或读取 `tdts` 白名单。

### 实时刷新模式（本地服务）

```powershell
D:\ai-workspace\shared\scripts\python.cmd `
  src\serve_dashboard.py `
  --base-url "<进展 Base URL>" `
  --issue-base-url "<问题 Base URL>" `
  --innovation-base-url "<创新大赛 Base URL>" `
  --lark-cli "<lark-cli.cmd 路径>" `
  --config "src\dashboard_config.json" `
  --filter-field "是否上周三例会"
```

默认从项目专属端口段 `8710—8719` 启动，通常打开 `http://127.0.0.1:8710/`（`--port` 可指定临时端口，`--no-open` 不弹浏览器）。8765曾被01和02历史版本共同使用并留下浏览器旧页面，不再作为默认入口。启动时首次抓取成功，以及页面内每次点击「AI 看板／重新生成」成功后，都会只读刷新进展、问题与创新大赛三个 Base 视图，并同步覆盖当天的 `output/YYYY-MM-DD(WXX)-TDT技术项目状态看板.html`；跨日期后自动创建新文件。同一模板以 `file://` 双击打开时使用内嵌快照，不依赖本地服务、飞书登录态或网络。

运行中的服务会在每次 Base 刷新前检查 `src/generate_dashboard.py`：文件未变化时直接复用当前模块；发生变化时先隔离编译并使用候选模块完成一次完整抓取和离线产物写入，全部成功后才切换为新模块。热更新编译或首次刷新失败时返回明确错误，页面继续显示上次成功数据，且不会覆盖当天离线 HTML；修正代码后可再次点击「重新生成」。该机制只覆盖数据生成模块；HTML／CSS／JavaScript 修改后需要刷新浏览器页面，`serve_dashboard.py`、启动参数或启动脚本变化后仍需重启 `start-dashboard.cmd`。代码本身存在语法、依赖或接口错误时，重启不会绕过错误。

更省事的启动方式：双击项目根目录 `start-dashboard.cmd`（含真实进展／问题／创新大赛 Base URL，gitignore 不入库；格式见 `start-dashboard.example.cmd`，固定使用正式 `V1.3.0` 模板和 `src/dashboard_config.json`，可追加端口等运行参数）。脚本通过 `/api/health` 核对固定项目身份 `tdt-project-status-dashboard` 与当前源码构建标识：当前版本已运行时直接复用；端口被其他项目占用时在本项目专属的 `8710—8719` 中选择空闲端口，不会打开、终止或接管其他项目。打开地址会携带当前 `build_id`，强制浏览器执行新导航，避免聚焦历史旧标签页。显式传入 `--port` 时仍按指定端口运行，同端口仅允许替换命令行明确属于本项目的旧看板服务。页面刷新遇到短暂网络中断时会有限重试，Base权限、字段或解析错误仍立即显示明确错误。首页每次请求也会重新读取模板文件，避免继续展示旧代码。`start-dashboard.example.cmd` 与正式脚本保持相同启动逻辑，但继续只保留占位符，避免正式Base URL进入Git。

## 数据来源与依赖

- 数据读取走 lark-cli（凭据在本机登录态，不进代码与仓库）；进展／问题 Base URL 均在运行时传入，不硬编码。
- 看板已纳入范围的记录和已映射字段以 Base 为唯一业务事实来源：真正空值显示空白，其他非空值必须留下可见、可追溯的呈现。允许不改变业务含义的格式化、徽章、拆分、排序、分组、聚合和已确认归一化，但不得脱离 Base 补数或把非空值静默清除。
- 该规则不依赖 `AGENTS.md` 才能生效：生成脚本通过中央函数 `mapped_base_value()` 执行取值原则，正式模板通过 `cellText()` 执行同构渲染规则，`tests/test_dashboard_runtime.py` 与 `tests/test_empty_table_cells.mjs` 持续校验非空值保留和独立业务边界；复制完整运行资产后规则随功能一起迁移。
- 该原则只覆盖“已纳入范围的记录＋已映射字段”。记录筛选、最近两周、最新日期块、字段别名回退和统计口径仍按本节明确规则执行；这些有损范围规则以及固定赛道数、PM 空值归组等独立业务逻辑，不随普通映射修复隐式改变。
- 记录层级只看多维总表字段「TDT/子任务」：值为「TDT」即父阶，值为「子任务」即子任务；「父记录」仅作为子任务关联所属 TDT 的连接字段，不参与层级判断。
