# 多维总表书写规则

适用于团队维护「详细进展」和「遗留问题」看板。

填写顺序很简单：先在飞书多维总表填写或更新内容，再到看板点击「重新生成」。看板只读取总表，不会回写总表。

## 先记住这 3 条

1. 一条子任务或一条遗留问题，对应一行记录；不要把多个独立事项混写在同一行。
2. 想让详细进展上看板，请将「是否上周三例会」选择为「是」，并填写正确的「子任务 PM」。
3. 功能宪法：总表中写入的内容会体现在看板中。

---

## 一、详细进展看板怎么写

填写位置：飞书「TDT技术项目总表」中用于周例会的视图。

### 1. 先保证子任务能被收录

| 总表字段 | 怎么填 |
| --- | --- |
| `是否上周三例会` | 需要在本周详细进展中汇报的子任务，选择「是」。未选择「是」不会进入详细进展看板。 |
| `子任务 PM` | 选择实际汇报人。看板会把子任务放在该 PM 名下；请优先填写，不要依赖系统回退。 |
| `TDT/子任务` | 确认记录类型是「子任务」，并填写准确的子任务名称。 |

### 2. 看板九列与总表字段对应关系

| 看板显示列 | 对应总表字段 | 最简单的填写方法 |
| --- | --- | --- |
| 子任务名称 | `TDT/子任务名称` | 填写简洁、准确的子任务名称。`项目编码`会随子任务一并显示。 |
| 价值决策 | `价值决策` | 直接选择正确日期。看板会自动显示为日期。 |
| 结项时间 | `TDR3预计` | 直接选择预计结项日期。 |
| 风险状态 | `风险状态` | 按实际选择 `/`、低风险、中风险或高风险。没有填写时，看板显示为空白。 |
| 项目阶段 | `阶段查找` | 这是关联查找字段，确认来源数据正确即可；不要用其他文本字段替代。 |
| 控制点 | `阶段控制点` | 每个控制点单独一行，统一使用「序号、事项 MM/DD」格式。 |
| 本周进展 | `最新进展描述（TDT PM）` | 在最新日期段内，写在「本周进展：」后。 |
| 下周计划 | `最新进展描述（TDT PM）` | 在同一最新日期段内，写在「下周计划：」后。 |
| 风险 | `项目风险` | 只写需要说明的具体风险；没有内容就留空。 |

### 3. 控制点统一写法

每个控制点单独占一行，统一按下面格式填写：

```text
1、项目团队组建 01/30
2、PD评审 02/11
3、需求拆解 03/06
```

注意：

- 日期统一写为 `MM/DD`，例如 `01/30`、`07/24`。
- 使用中文顿号编号：`1、`、`2、`、`3、`。
- 不要使用 `1)` 或 `1）`。正文中的数量如 `76)` 容易被误读，统一改为 `1、事项内容` 最清楚。
- 控制点没有内容时，字段留空即可。

### 4. 本周进展和下周计划统一写法

这两列都来自同一个字段「最新进展描述（TDT PM）」。可以分段写，也可以连续写；两种写法都会进入看板。

分段写法：

```text
07/27：
本周进展：
1、完成交互评审，问题清单已闭环。
2、完成服务器部署联调。

下周计划：
1、输出交互优化方案，07/31前完成。
2、完成稳定性测试。
```

不分段写法：

```text
07/27：本周进展：1、完成交互评审，问题清单已闭环；2、完成服务器部署联调；下周计划：1、输出交互优化方案，07/31前完成；2、完成稳定性测试。
```

填写技巧：

- 日期必须写在新一行开头，格式为 `MM/DD：`。
- 标签统一写「本周进展：」和「下周计划：」，标签后的内容会进入对应看板列。
- 多件事时，一件事一行，并使用 `1、`、`2、` 编号。
- 尽量写“做了什么＋结果／时间”，例如「完成服务器部署联调」；不要写很长的一整段话。
- 同一字段保留多周历史时，看板只展示最新日期段。推荐每周只保留最新一段，旧内容请放在其他周报留档位置。
- 若编号后紧跟英文正文，请留意多维表格会自动识别蓝色超链接：数字＋`.`＋英文正文之间没有空格时，会影响看板录入。这是多维表格自身的功能特性，不是看板功能。
  - ❌️ `1.ID`
  - ✅️ `1. ID`
  - ✅️ `1、ID`
  - ✅️ `1、 ID`
  - 中文顿号 `、` 不会触发超链接；使用英文句点时，必须在 `.` 后加一个半角空格。

## 二、遗留问题看板怎么写

填写位置：飞书「TDT周例会遗留问题统计」视图。

### 1. 先按这 4 条填写

1. 一条遗留问题一行，不要把两个问题写进同一条记录。
2. `Week` 必填，且只填数字周次，例如 `31`；不要写 `W31`、`2026 W31`。
3. 看板固定展示最新一个有效周次及其前一周。例如最新是 `31`，看板展示第 `30` 周和第 `31` 周。
4. 某周没有遗留问题时，新建一条只填写 `Week` 的记录，其余字段留空，作为该周的空周标记。

### 2. 看板字段与总表字段对应关系

| 看板显示列 | 对应总表字段 | 最简单的填写方法 |
| --- | --- | --- |
| Item | `Item` | 填连续序号，例如 `01`、`02`、`03`，方便同一周排序。 |
| 子任务名称 | `TDT项目子任务名称` | 填准确的子任务名称，建议与「TDT技术项目总表」保持一致。 |
| 任务 | `任务` | 用一句话写清待解决事项。 |
| 当前进展 | `当前进展` | 写当前状态、已完成动作或卡点。 |
| 计划完成日期 | `计划完成日期` | 直接选择计划完成日期。 |
| 调整日期 | `调整日期` | 计划变化时再填写调整后的日期；没有调整则留空。 |
| 实际完成日期 | `实际完成日期` | 完成后直接选择实际完成日期；未完成则留空。 |
| 提出人 | `提出人` | 填提出问题的人。 |
| 责任部门 | `责任部门` | 填实际负责推进的部门。 |
| 责任人 | `责任人` | 填唯一、明确的推进责任人。 |
| 任务状态 | `任务状态` | 从字段已有的下拉选项中选择，不自行输入近义词。 |
| 周次分组 | `Week` | 只填数字周次；该字段只用于看板分组，不作为表格列显示。 |

### 3. 推荐示例

| Week | Item | TDT项目子任务名称 | 任务 | 当前进展 | 计划完成日期 | 责任人 | 任务状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 31 | 01 | AIGC曙光增强 | 完成交互问题闭环 | 已完成问题复现，待发布修复版本 | 2026/07/31 | 张三 | 按下拉选项选择 |

### 4. 提交前检查

- `Week` 是否是纯数字。
- 一个问题是否只占一行。
- 日期是否用日期字段选择，而不是写在长文本里。
- 责任人和责任部门是否明确。
- 已完成的问题是否补充实际完成日期和任务状态。
- 没有内容的字段是否真正留空。

---

## 最后一步

完成填写后，打开看板并点击「重新生成」。如果内容没有变化，优先检查：

1. 详细进展的「是否上周三例会」是否为「是」。
2. 最新进展是否使用了「日期：＋本周进展：＋下周计划：」模板。
3. 遗留问题的 `Week` 是否填写为纯数字。
4. 是否刷新的是当前使用的正式看板页面。
